# 知识模块重设计：内容优先，主题自动归属，项目可选

状态：内容优先的第一批功能已实现，范围与使用方式见第 12 节。本文中的原始问题记录描述改造前状态；未实现的媒体解析、目录持续同步等仍按后续阶段处理。普通知识不再默认要求生成项目名和选择目录。

## 1. 本次构建失败的事实与根因边界

截图同时显示“候选 0 个文件、纳入 0 个”“No documents scanned”和“《主题地图》没有可用的证据文件”。源码中的 `Runtime::wiki_build_article` 在证据包为空时直接拒绝构建；完整构建流程此前仍会规划主题，通用默认计划含“主题地图”等固定主题。因此这里不是已经证实的模型服务异常，而是没有可用输入仍走到了文章生成阶段。

项目目录、已保存的知识、可供本次构建使用的证据是三件不同的事。上一轮创建目录并保存 Wiki 台账，只解决了知识保存和归属，没有把所有内容类型转换为项目扫描器可读的文件证据。创建空文件夹不会自动产生代码或文档。目录为空、扫描规则排除、解析失败、资料尚未启用、台账与来源索引没有接通都可能造成零证据；究竟是哪一种，必须以该次构建快照核对，不能仅凭红色提示确定。

不应删除证据检查来“修好”报错。应改正任务路由：保存一篇已有文章不需要重新生成主题地图，更不需要先扫描项目文件。

源码依据：
- `apps/desktop/src/components/KnowledgeHubPanel.vue`：默认 `source = 'wiki'`，项目 Wiki 排在本地知识库之前，操作必须先选项目。
- `crates/dandelion-core/src/runtime.rs`：`wiki_build_llm`、`wiki_build_article`，规划后再检查单篇文章的证据包。
- `crates/dandelion-core/src/wiki_build.rs`：`REQUIRED_TOPICS_GENERIC`、`default_plan_generic`，通用知识也被套用固定文章结构。
- `crates/dandelion-core/src/wiki_index.rs`：项目文件扫描器按代码、文档、配置扩展名收集输入。
- `crates/dandelion-core/src/store/sqlite.rs`：已有 KnowledgeDocument、版本、片段、空间及多空间关联能力，可以复用，不需要另建一套知识存储。

## 2. 产品模型

最小单位是“知识条目”。主题模块是条目的组织与阅读视图；项目是特殊业务上下文，不是条目存在的前提。

| 对象 | 职责 | 是否必选 |
| --- | --- | --- |
| 知识条目 | 文章、代码及解释、视频及笔记、摘录、对话整理 | 保存时只需内容 |
| 来源与附件 | 原文件、网址快照、对话、视频、模型生成记录 | 按来源类型记录，不能伪造 |
| 主题模块 | 按语义组织条目，例如 Go → 并发编程 | 模型可后台建议和归类 |
| 标签与关联 | 语言、用途、先修关系、相关知识、项目引用 | 可选，可多对多 |
| 项目文档 | 对代码仓库、整套项目资料进行扫描、构建与维护 | 仅项目场景需要 |
| 知识库边界 | 所有者、权限、外发策略和本地存储范围 | 系统建立默认个人知识库；不要求每次选择 |

“个人知识库”是存储与权限边界；“主题模块”是内容组织方式。不能把这两者合并，否则模型的分类行为会意外改变权限。

同一条 channel 笔记可以属于“Go”和“并发编程”，也可以被某项目引用。移动主题不会移动原文件、复制正文或改变条目 ID。没有合适主题时留在“待归类”，照样可阅读、编辑和检索。

## 3. 五种入口，统一保存

### 从对话保存

用户说“把 Go 核心知识整理到知识库”：先保存完整知识条目，记录来源会话和消息；再异步生成标题、摘要和主题关联。对话返回可点击的已保存条目，明确显示“已保存，正在归类”。不弹项目创建表单，不要求选择文件夹。未保存成功时保留待保存内容并提供重试，不能只有口头承诺。

模型生成的内容注明“模型整理”，与可核对的外部资料分开；保存不等于事实已经验证。未核实的观点不得以“项目事实”或“官方结论”注入后续回答。

### 新写文章 / 代码

新建内容、粘贴正文或代码即可保存。代码条目包含语言、代码、解释和可选运行说明；默认不执行代码。支持单独维护、版本历史和手动修改。用户写好的正文就是原始内容，不必为了成为“知识文章”再走一次模型重写。

### 导入文件或链接

先保留原文件或来源，再解析内容；解析失败仍能找到、下载或重新处理原资料。链接保留 URL 和抓取时间；不能读取全文时明确标注，不能假装已经学习了整篇网页。默认本地存储位置在首次设置时确定，逐条导入无需选项目目录。

### 视频及解释

保留视频文件或链接、用户笔记、可选字幕。只有在转写/解析能力确实可用并处理成功时，才能按时间码定位和检索视频内容；只有链接或未转写视频时，检索范围只包括标题和用户笔记。不能把视频文件名当成已理解其内容的证据。

### 导入项目文档

独立入口“添加 → 项目文档”：选择仓库/目录、预览可读文件、确认后沿用现有扫描、项目概览、架构与源码引用等效果。没有代码的完整文档项目按实际材料类型规划目录，不强制生成架构页或固定四篇文章。项目内容同时进入统一知识检索，项目视图保留原始层级与版本。

## 4. 保存、处理、归类与生成必须解耦

保存事务完成后，条目即有稳定 ID 和原始版本。分类与模型任务不能成为保存成功的前置条件。

| 状态维度 | 状态示例 | 失败影响 |
| --- | --- | --- |
| 保存 | 未保存、已保存 | 只有此步骤失败才表示未落盘 |
| 解析 | 无需解析、处理中、已完成、不支持、失败 | 保留原件和用户笔记 |
| 归类 | 待归类、已归类、需确认、整理失败 | 不影响原始条目使用 |
| 检索 | 待索引、可检索、索引失败、仅元数据可检索 | 不把不可检索说成可检索 |
| 衍生文章 | 未生成、生成中、已生成、待更新、生成失败 | 不覆盖条目原文与上一成功版本 |

不使用一个全局“知识构建成功/失败”覆盖这些状态。重试只处理失败阶段，避免重复保存、重复付模型费用或反复创建模块。

对于个人知识，“保存并用于对话”可以是显式默认动作；“仅保存为草稿”是可选动作。原内容的检索可用性与模型衍生内容的审核分别管理。共享资料和现有权限策略不能被默认个人流程绕开。

## 5. 模型自动归属规则

1. 根据条目类型、正文、代码语言、原来源和用户修正生成标题、摘要及主题候选。
2. 先在用户有权限的既有主题中匹配；优先复用“Go”，避免同时创建“Golang”“Go语言”“Go编程”三个模块。
3. 高可信、可撤销的既有模块关联自动执行；多义、低可信、新模块创建和模块合并进入建议区。主题支持逐步生长，不为每条内容创建一个新模块。
4. 单篇内容也可以先独立存在，不强制等待形成模块；已有条目形成稳定主题后再建议聚合模块。
5. 手工指定、固定的主题和标题优先于模型，不因后续批处理被覆盖。分类修订留记录，可撤销，不移动实际文件。
6. 归类任务绑定条目版本和分类规则版本；旧任务的晚到结果不能覆盖新编辑、删除、权限变化或用户已修正的归属。
7. 不把模型输出的分类置信度直接当成可信概率。结合检索匹配、重复检测、规则及实际使用反馈校准策略。
8. 分类请求遵守 local_only 等外发策略。没有可用本地模型、且禁止外发时保留“待归类”，不能偷偷发到云端。

主题模块默认展示已有条目和来源。模型生成“模块综述、学习顺序、知识关联图”是可选增强，不是模块能否存在的条件。

沿用蒲公英现有浅色与紫色选中态，不重新发明品牌。设计重点是内容的可见、可读和可找，不增加运营式指标大卡片。

- 色彩：主背景 #FAF9FC、侧栏 #F2EFF8、阅读面 #FFFFFF、正文 #292335、辅助文字 #77717F、选中紫 #7857D4。
- 字体：沿用 Geist 与中文系统字体；正文 14–16px、列表标题 14px、页面标题 24px；代码使用现有等宽字体。
- 布局：左侧导航 220px，中间内容列表可伸缩，选中后显示阅读区；窄窗口改为列表与详情单页切换。
- 原则：知识列表作为默认首页；主题负责组织；项目保持可达但不抢占默认入口。代码、文章、视频的阅读方式各自适配。

### 全部知识

紧凑列表呈现类型、标题、摘要、处理状态、主题和修改时间。保存成功的条目立即出现，不因后台整理未完成而消失。“添加知识”菜单包含文章、代码片段、视频/链接、导入资料、项目文档。目录选择只在导入文件/完整项目或修改存储位置时出现。

### 条目阅读

以正文为主。文章直接阅读和编辑；代码显示语言与解释；视频显示播放器/原链接、用户笔记和可用的时间码。元信息放侧栏或折叠区，错误不占据整个阅读区。来源与版本始终能核对，不混淆模型生成和原始材料。

### 主题模块

展示模块简介、相关条目、可编辑的子主题和模型的归类建议。一条内容可出现在多个主题，不重复存储。只有用户需要时才“整理为综述”，明确列出选用的材料及尚未处理的内容。单条目主题可直接展示条目，不凑出空的“主题地图”。

### 项目文档

保留现有完整项目体验：项目目录、扫描覆盖、代码和文档结构、Wiki 页面、增量更新、出处定位。项目边界在这一层明确，不反向要求所有普通知识都建立项目。

## 7. 从根源处理“构建失败”

生成前进行来源预检，输出来源总数、可读内容数、被跳过原因和可进行的任务。预检不消耗模型生成调用。

- 0 个可读来源：不调用规划模型，不生成默认主题。提示“暂无可用于整理的内容”，提供添加内容、检查解析、检查启用状态入口。
- 有完整手写/模型整理文章：直接保存与阅读；可选润色，不强制重建。
- 有对话或代码片段：以对应条目版本和片段位置作来源，不要求伪造物理文件行号。
- 视频无字幕：只按标题/用户笔记检索，显示待转写；不尝试引用不存在的视频转写。
- 多个可读来源：按实际内容规划主题，文章依据不足则跳过该目标并说明原因，不把所有条目判为保存失败。
- 模型服务异常：显示“自动整理暂未完成，原内容已保存”；仅在确有上一成功生成版本时才显示“上一版本仍可读”。

每个阶段有独立的结构化错误：no_readable_sources、parser_failed、model_unavailable、generation_failed、index_failed、cancelled。底层 evidence 错误放详情中，用户页面直接说明缺什么、保留了什么、如何继续。

## 8. 工程实现边界

复用 dandelion-core 的统一 Runtime、单一 Agent loop、现有资料版本/片段/RAG/权限体系。Vue 负责展示和收集选择，不能新增另一套模型工作流。

逐步引入稳定的 item / item_version / asset / module / item_module_link / enrichment_job / citation 语义。可以复用或扩展现有表，而不是照此名称复制新表。原始版本身份与主题/空间关联分开；分类不能改变所有权、读取权限或外发规则。来源引用支持资料版本与片段、文件行、对话消息、视频时间码，均回到同一权限与版本校验入口。

自动检索顺序仍以权限和相关性为准，项目只在用户正在讨论该项目时参与上下文排序，不能全局压过其他知识。源条目优先核对；生成综述可用于导航，回答中的事实最终回链到真实来源。

项目文档构建与普通知识整理共享底层存储、模型和检索服务，但使用不同的任务计划：前者扫描目录并建立源码证据；后者处理条目版本与附件。不能再把普通知识虚拟成空项目目录后复用整条构建链。

## 9. 迁移顺序与验收

1. 先补来源预检和分阶段状态，消除零输入仍调用模型的错误路径。
2. 打通无项目条目保存；旧的待绑定 Wiki 草稿提供“保存为独立知识”出口，不丢内容、不强制批量建立项目。
3. 默认首页改为全部知识；保留项目 Wiki 作为项目文档入口，既有文章与引用不迁坏。
4. 引入可撤销的主题归属与待归类列表，再逐步加入自动关联。
5. 补齐视频等媒体的解析能力；没实现之前如实标注，不把上传等同于理解。
6. 最后优化主题综述、知识关联与项目跨主题阅读。

必须通过的场景：
- 一篇文章、一个代码片段、一个视频及说明，均能不创建项目保存。
- 原文已保存后模型不可用，内容不丢、可编辑，重试不重复导入。
- 分类未完成、分类失败或用户撤销分类，条目仍存在。
- 主题改名/合并不改变条目身份、权限和历史引用。
- 自动归类不覆盖手动修正，过期异步任务不能覆盖新版本。
- 0 来源的整理请求不消耗文章生成调用；有效的对话/文章内容不被错误判成无证据。
- 无转写的视频不会在回答中被当成已读内容引用。
- 完整项目导入仍保留扫描、增量更新、源码定位与受保护的人工修改。
- 本地与 Claude Code / Pi / OpenCode 对话都使用同一检索、权限与来源规则。

## 10. 明确的范围边界

本方案不是“关闭项目功能”，也不是“让模型随意生成并归档文件夹”。是将内容保存、语义组织、项目文档三个职责分开。本节为最初设计阶段的范围说明；后续实现以第 12 节为准，视频转写仍不在已实现范围内。

## 11. 从 README 导入失败重新审视收集入口

### 已核查的现状

桌面 `knowledge_parse_local_file` 对 Markdown 直接读取 UTF-8 文本，不调用模型；去掉 BOM 与首尾空白后为空，就返回“未能从文件提取可索引的文本”。不支持格式、读取失败与非 UTF-8 各有其他错误。仅凭报错不能确定用户选择的具体 README 路径与内容，也不能推断所有 Markdown 都不可用。

更重要的是当前 `knowledge_import_pick` 顺序为“读取 → 解析 → 入库”。解析失败只记录来源路径与错误，未持久保存原文件副本。当前选择器仅覆盖 txt/md/markdown/pdf/html 等类型，不能满足任意代码、图片或视频片段收集。当前“本地资料”本质偏向文本检索输入管理，尚不是完整的个人知识收集产品。

### 产品收敛：一个知识入口，项目是专用视图

首页不再要求用户理解两个知识系统。个人知识统一展示独立条目，提供全文搜索、最近保存、待处理、主题和项目文档入口。项目文档拥有扫描、源码关系与 Wiki 构建能力；同一条知识可以关联项目，但无需为了存在而建立项目。权限隔离和模型外发策略仍保留在底层，不因统一界面而取消。

文章、代码、视频等是条目的内容形态；文件夹只是来源和批量收集范围；主题是可撤销的语义关系；项目是上下文。这四个概念不能相互代替。

### 最重要的收集契约

1. 用户选择、拖入或粘贴后，先建立条目和原始版本；本地文件默认复制到受管附件区，记录原路径、大小与内容哈希。源文件改名、移动或删除后，已收集副本仍可打开。
2. 数据库元信息与附件采用可恢复的提交流程：临时文件写入、校验、原子落位、登记任务；启动时清理/恢复中断，不留下“显示已保存但没有附件”的条目。空间不足和权限错误明确表示“未保存”。
3. 解析失败时显示“文件已保存，正文暂不可检索”，支持打开原件、补充笔记、查看原因与重试。未保存副本的旧失败记录必须标为“仅记录了路径，需要重新选择文件”，不能显示成已保存条目。
4. 空 README 可以保存为空文件附件，显示“文件为空，暂无正文”；补充笔记后可检索笔记。只按名称命中时标注为文件名匹配，不把文件名当成文件正文。
5. 格式、编码、扫描版 PDF、读取权限、空文件、模型错误分别说明。编码失败可预览候选解码结果并确认；不能静默替换乱码后当成成功。
6. 模型整理、分类、向量索引均为后台可重试任务；关闭窗口后可恢复。已保存不代表所有处理完成，可检索也不代表模型已经核实内容。
7. 同文件同版本再次添加不重复创建正文，可补充来源关联；同路径内容变化建立新版本。相同代码附有不同解释时允许独立条目，不按哈希误合并用户笔记。
8. 批量导入先预览支持/待解析/跳过的范围；默认不递归导入隐藏目录、构建产物或凭据，不跟随目录链接。跳过列表可查看，不把过滤的内容隐瞒为完整导入。

### 首页和操作的具体约束

沿用第 6 节的颜色与字体，列表与阅读器作为主要结构。删除顶层的必选项目/资料库选择器；默认个人范围由系统建立，切换权限范围作为次要管理操作。设计复核：继续将“文章生成”放在首页主按钮会把收集流程重新引向构建，因此主按钮固定为“添加知识”。

```text
知识                         搜索标题、正文和代码             添加知识
──────────────────────────────────────────────────────────────────
全部知识       最近保存 / 类型筛选                  [选中内容阅读区]
最近保存       Go 并发中的取消方式                    原始内容
待处理         代码  可检索                           我的笔记
收藏           README.md                             主题 / 项目关联
               文件为空  原件已保存                   来源与版本
主题           调度器讲解
  Go           视频  笔记可检索，视频未转写
  并发编程
项目文档
  蒲公英
```

“添加知识”只提供写笔记、粘贴代码、添加文件/文件夹、添加链接。项目文档入口内部再选择目录和构建；不把源文件夹默认变成语义主题。导入后自动选中新增条目，先展示原文；处理状态就地更新，不跳转到空的模型文章目录。

主题页默认是已归属知识的聚合列表。模型简介和综述是可选内容；没有综述也可用。分类待定时保留在全部知识和待处理区，高可信的既有主题关联可自动执行，新主题、合并主题和多义归属提供建议。手工固定归属不会被模型覆盖。

### 目录更新与可携带性

第一阶段明确为一次性收集。后续若增加目录同步，需要用户单独开启，展示同步范围和变化记录；原文件删除不自动抹去收藏与笔记。重命名、内容更新和移除分别处理。个人笔记与原文分开存储，更新来源不能覆盖笔记。

支持导出原文件、Markdown 笔记与关联元信息。导出结果不依赖模型，不需要本软件才能阅读；引用携带稳定来源版本，避免更新后引用悄悄指向新正文。

### 第一批可用性交付标准

先完成文本、Markdown、常用代码片段的收集、阅读、编辑、关键词检索、对话出处与原文定位，以及任意附件加笔记。PDF 文本解析作为明确支持项；图片识别、视频转写和语义嵌入按实际实现逐步开放，不把附件保存宣传成理解媒体内容。

用实际用户任务验收：
- 拖入一份非空 Markdown，立即读到正文，索引完成后按正文问句命中并回到原段落。
- 空 Markdown 留在列表中且明确说明无正文，不被当作已理解的知识。
- 粘贴 20 行 Go 代码及解释，无项目直接保存，再次提问能定位代码。
- 收集一个视频并补笔记，仅笔记和元信息可检索，视频内容未转写时不产生时间码引用。
- 导入 100 个混合文件，已保存、失败、跳过各自有逐项结果；重试不重复导入成功项。
- 模型离线时上述收集、阅读与本地全文查找可用；自动归类排队并可稍后重试。
- 源文件移走后保存副本与笔记可读；项目 Wiki 仍能处理真实项目及引用源码。

以上为待实施设计，不表示附件存储、同步、媒体解析或新首页已完成。


## 12. 已实现的内容优先版本

- “知识”默认打开全部条目，侧栏含最近保存、待处理、收藏和主题；项目文档折叠显示，可直接选目录添加。旧的资料库、权限和文章管理保留在次要入口。
- 笔记、文章、代码、链接均无需项目即可保存；标题可省略，从首段提取。内容复用原资料版本与片段索引，保存后在本地可检索。链接只记录地址与笔记，不声称已抓取网页全文。
- 文件先复制到本机的受管附件目录，以内容哈希寻址；保存一个带处理状态的条目后再提取正文。Markdown、文本、常用代码和可提取文本的 PDF/HTML 可解析。空文件、编码错误和未支持格式均保留原件及可编辑笔记，提供重新提取和原件导出。
- 文件夹一次性收集，确认数量与部分文件名后执行；隐藏项、构建目录、目录链接和常见凭据扩展名跳过，结果可展开。还没有持续目录监控。
- 重复导入相同路径、相同快照不会产生重复条目或版本。来源变化建立新版本，保留用户笔记和手动归属；原件按版本关联。删除条目时清理已无其他版本引用的附件副本，源电脑中的文件不删除。
- 模型整理默认关闭，开启“允许当前模型整理并引用我的个人知识”后，按已有外发策略发送相关摘录。后台按保存记录中待处理状态逐项归类，重新打开页面可继续；已有主题可自动关联，新主题以建议显示。手动归属优先；旧版本的晚到结果不能覆盖新版本。没有新增模型服务或 Agent 循环。
- 对话明确请求保存到知识库时，即使当前有工作项目，也将成功完成的答复保存为独立知识；明确要求项目 Wiki 时沿用项目路径。完整回答只保存为一个条目和一张通知卡片。无项目的显式 Wiki 写入也可落为独立知识；一般模型提议仍保留为草稿，提供“保存为独立知识”按钮，不自动生成项目名称。
- 资料检索和来源引用继续复用现有本地 RAG 服务与外部引擎桥接；local_only 资料不会因新页面而绕过外发策略。未解析媒体只索引标题与笔记。
- 零项目来源在模型调用前阻止构建；项目目录迁移与旧目录编译串行，写入前确保使用已解析的项目知识目录，避免后台迁移与台账写入竞态。

使用：在“全部知识”添加内容；需要模型归类或在云端模型回答中引用个人内容时，明确开启页面底部的模型使用选项。可直接在主对话提问，来源能回到对应资料版本。完整项目在“项目文档”中选择真实目录并构建。

界面使用真实 Vue 组件与独立示例数据验证过笔记保存和代码阅读；存储、原件恢复、重复导入、检索、手动归属及模型权限使用真实 Runtime/SQLite 回归测试。界面示例不是用户实际资料，测试不修改用户现有内容。

尚未实现：图片 OCR、视频转写/时间码检索、网页全文抓取、目录持续同步和新的语义嵌入模型。附件保存与笔记检索可以先使用，不把这些后续能力标记为已完成。
