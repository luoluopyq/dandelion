# 本地知识库与对话检索

## 与项目 Wiki 的边界

| | 项目 Wiki | 本地知识库 |
| --- | --- | --- |
| 主要用途 | 阅读、理解和维护一整个项目的代码及文档 | 长期保存和检索独立资料与文章 |
| 输入来源 | 用户选择的真实项目目录与项目对话沉淀 | 导入的文件、粘贴文本、手写文章等 |
| 是否需要项目目录 | 需要；目录必须有可读取的项目文件，才能生成有文件出处的模型文章 | 不需要用户先创建项目或选择项目目录 |
| 模型生成的作用 | 基于扫描来源生成项目概览、流程等文章 | 可选地把已有资料整理成文章；资料检索不以生成成功为前提 |

项目对话沉淀保存在内部台账，确认后可显示为对应的知识页面；它不会自动变成项目目录中的源文件。因此目录为空时，台账仍能存在，但不能据此宣称已有文件证据并构建项目文章。快速扫描页面的存在，也不代表已成功完成模型构建。

零散知识现在默认在“全部知识”中独立保存，主题归属不要求创建项目。旧的对话草稿可以直接“保存为独立知识”；无项目对话明确请求保存的完整回答也会进入个人知识。完整实现范围见 [知识模块重设计第 12 节](knowledge-content-first-design.md#12-已实现的内容优先版本)。

## 使用方式

1. 在「知识 → 全部知识 → 添加知识」写笔记、粘贴代码或添加文件/文件夹。完整项目通过侧栏「项目文档」处理。原有资料库的管理入口保留在「资料与权限管理」。
2. 新的个人条目保存后立即进入本地检索；文件先保存原件再解析，空文件或未支持格式仅检索标题与笔记。旧管理页的草稿启用流程继续保留。
3. 直接在蒲公英原生、Claude Code、Pi 或 OpenCode 的主对话里提问，无需选择或绑定知识库。
4. 原生执行、计划模式及外部引擎执行模式通过现有只读检索工具按需查找所有可读取的本地知识。问答模式没有工具调用，因此由核心检索相关片段，只有命中时才提供依据；未命中不添加无关知识提示。
5. 助手可在回答中引用可点击的出处，打开对应的原始资料版本与片段。

文件夹是一次性导入，不是文件监控或持续同步。资料问答不需要先生成知识文章。
模型使用遵守资料所属知识库的外发策略，个人知识默认仅在本机使用；需要模型整理和引用时，显式开启页面底部选项。
「资料与权限管理」中的「知识文章」页单独负责生成、更新和阅读整理后的文章，保留构建取消、错误和原文引用能力。

## 检索实现

- `knowledge_chunks_fts` 是 SQLite FTS5 trigram 派生索引，支持中文连续短语和英文查询。
- 全文结果使用 BM25 排序，完整短语命中优先；两字符词使用范围内的子串匹配补充，文件名也参与定位。
- 旧数据库首次打开时自动补建索引。插入、更新、删除分块的数据库触发器维护索引，兼容资料库与原有 corpus 写入路径。
- 统一空间检索优先返回直接资料片段，再补充知识文章和已有向量检索结果，相同摘录去重；不同空间轮流分配返回名额。
- 摘录围绕匹配位置截取，而不是始终取文章开头，并保持 UTF-8 字符完整。
- 这是本地全文检索增强生成（RAG），没有新增语义 Embedding 模型或模型下载。已有的哈希向量兼容通道继续保留，不能把它等同于训练后的语义嵌入。

`knowledge_retrieve` 是新的排序读取；原有 `knowledge_search` 保持字面匹配语义，避免破坏已有 API 调用。
按需检索工具和问答模式继续调用同一个 Runtime 空间检索服务；没有新增 Agent 循环或 ACP 事件类型。执行、计划模式不会在每次发送时预先塞入资料。外部 Agent 通过现有本机桥接调用 `dandelion_knowledge_search`：Claude Code 使用 MCP 配置文件，OpenCode 合并 MCP 配置，Pi 加载由同一工具目录生成的扩展。检索工具每次调用重新发现本地范围并核对权限，已打开的对话也能发现后来导入的资料。

## 版本与权限

只有已启用、未撤回、未删除且当前用户有权读取的资料参与检索。
绑定固定版本的空间继续按固定版本检索；自动跟随的空间使用当前生效版本。
发布资料版本使用一个数据库事务完成，避免中途失败使旧版退出却没有新版接替。

原始资料引用包含空间与不可变片段 ID，打开时重新检查权限、关联关系和撤回状态。
被新版本接替的旧版资料仍可核对；撤回、删除或解除空间关联后不能继续从该引用读取。
知识文章链接打开当前文章，并明确标注为当前版本，不假称为历史快照。

未启用资料的管理预览只对来源所属知识库的编辑者开放。外部模型使用策略仍由核心层检查：
「仅在本机使用」的资料不会作为原文发送给云端模型。按需检索和问答模式都会检查同一套权限。

## 配置

以下参数都通过核心 `Settings` / `settings.json` 配置：

| 配置 | 作用 |
| --- | --- |
| `dandelion.space.searchMaxHits` | 每轮检索的片段数 |
| `dandelion.knowledge.excerptBytes` | 每条匹配摘录的字节上限，默认 1200 |
| `dandelion.knowledge.chatMaxSpaces` | 保留给旧版绑定接口兼容；自动发现不受该数量截断 |
| `dandelion.corpus.maxInjectBytes` | 注入对话的资料总字节预算 |

FTS5 行为参考：[SQLite 官方文档](https://www.sqlite.org/fts5.html)。

## 验证

`g25_rag` 覆盖自然语言中文检索、长文末尾证据、相关性排序、文件名定位、草稿预览与启用、
升级补索引、删除、权限与历史来源失效，以及无需绑定的按需工具检索、纯问答检索、超出旧数量限制的资料发现与未命中时不添加上下文。
现有空间关联、固定版本、外发策略、原文引用和 corpus 兼容测试继续使用原来的断言。
前端引用解析测试覆盖非法协议、路径穿越、非法编码和中文文章文件名。

## 外部 Agent 的本地知识检索

- 外部引擎的执行模式按需查找本地资料与知识文章，不要求选择知识库，不把资料全文作为每轮提示。
- 知识读取独立于 Wiki 写入开关。关闭 Wiki 写入，仍可检索；已有项目/空间 Wiki 令牌不自动获得跨库读取权限。
- 引擎启动时明确记录模型是否可能离开本机。云端模型不能读取 `local_only` 内容，即使蒲公英原生配置的是本地模型；使用蒲公英本地模型的外部引擎则按本地路由处理。
- 同一令牌每次检索都重新发现可读空间、复核资料生效状态和外发策略。策略收紧、撤回、删除或取消读取授权会即时影响后续调用。
- 令牌绑定会话与工作区；关闭或取消会话、工作区/模型路由/能力变化时旧凭据作废。Pi 的网络请求传递工具调用的取消信号；受限模式在会话初始化后仅激活这一项检索能力，以兼容禁用扩展工具的新版 Pi。
- Claude Code 与 OpenCode 仅预先放行宿主提供的这一项只读检索工具，不放行 Wiki 写入、文件修改、命令执行或任意 MCP 工具。

协议核对依据：[Claude Code CLI](https://code.claude.com/docs/en/cli-reference)、[OpenCode MCP](https://docs.opencode.ai/docs/mcp-servers/)、[Pi 扩展](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/extensions.md)。
`g26_external_knowledge` 使用真实本机 MCP HTTP 请求覆盖无绑定检索、超过旧范围上限、Wiki 写入关闭、原文出处、模型路由、实时策略、归档/撤回/成员权限、旧令牌隔离与失效。
